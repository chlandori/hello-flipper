# Hello Flipper

A minimal [Flipper Zero](https://flipperzero.one/) application written in C, built with
**uFBT**. It opens a dialog on the device screen showing:

```
        Hello world
     I'm hello_flipper!
```

It also writes one line to the device log so you can practise both the GUI and logging
workflows. Use it as a template for your own FAP (Flipper Application Package).

---

## Prerequisites

| Requirement | Notes |
| --- | --- |
| Flipper Zero | With a microSD card inserted |
| USB-C cable | Must be a **data** cable, not charge-only |
| Python 3.8+ | `python --version` |
| VS Code | Recommended; uFBT generates build + debug config for it |
| qFlipper | Optional, for manual file transfer and firmware updates |

You do **not** need to install an ARM toolchain. uFBT downloads the firmware SDK and the
`arm-none-eabi` compiler for you on first run.

## Setting up your dev environment

### 1. Clone and create a virtual environment

```powershell
git clone <this-repo> hello-flipper
cd hello-flipper
python -m venv venv
```

Activate it:

```powershell
# Windows / PowerShell
.\venv\Scripts\Activate.ps1
```

```bash
# macOS / Linux
source venv/bin/activate
```

> Activate the venv in **every new terminal** before running `ufbt`. If you see
> `The term 'ufbt' is not recognized`, you forgot this step.

### 2. Install uFBT

```powershell
pip install ufbt
```

### 3. Let uFBT download the SDK

The first uFBT command bootstraps everything into `~/.ufbt` (roughly 200 MB):

```powershell
ufbt update
```

You should see it deploy the SDK and extract the toolchain, e.g.
`Deploying SDK for f7` → `Using version: 1.4.3` → `Downloading Windows toolchain..done!`.

### 4. Generate the VS Code configuration

```powershell
ufbt vscode_dist
```

This writes `.vscode/` (build task, debugger launch config, IntelliSense paths) plus
`.clang-format`, `.clangd`, and `.editorconfig`. **These are gitignored**, so every fresh
clone must run this command. Accept the recommended extensions when VS Code prompts you.


## Adding code and files

### The entry point

[hello_flipper.c](hello_flipper.c) follows the required shape:

```c
int32_t hello_flipper_app(void* p) {
    UNUSED(p);
    // ...
    return 0;
}
```

- The signature is always `int32_t <name>(void* p)`; return `0` for success.
- `UNUSED(p)` silences the unused-parameter warning.
- The function name **must exactly match** `entry_point` in the manifest.

### The manifest

[application.fam](application.fam) is Python-like and drives the whole build:

| Field | Purpose |
| --- | --- |
| `appid` | Unique ID; also the FAP filename |
| `name` | Label shown in the Flipper menu |
| `apptype` | `FlipperAppType.EXTERNAL` for FAPs |
| `entry_point` | Must match the C function name |
| `stack_size` | 1–2 KB is typical; raise only on stack-overflow crashes |
| `fap_category` | Determines the install path, `SD Card/apps/<category>/` |
| `sources` | Explicit list of `.c` files to compile |
| `fap_icon` | 10x10 1-bit PNG |
| `fap_icon_assets` | Folder of PNGs compiled into `<appid>_icons.h` |

> **Adding a new `.c` file?** You must add it to the `sources` list. This project pins
> `sources` explicitly instead of using uFBT's default glob — see
> [Troubleshooting](#troubleshooting) for why.

### Adding images

Drop PNG files into `images/`. uFBT converts them to Flipper's internal format and
regenerates `hello_flipper_icons.h`, which you include as:

```c
#include <hello_flipper_icons.h>
```

### Firmware API rules

The Flipper firmware is not a normal POSIX environment:

- Use FURI APIs, not libc: `furi_string_*` instead of `char*`/`str*`,
  `furi_delay_ms()` instead of `sleep()`, `furi_hal_*` for hardware.
- `malloc()` aborts on failure rather than returning `NULL`, so **never null-check it**.
- Pair every `_alloc()` with its matching `_free()`.
- Pair every `furi_record_open()` with `furi_record_close()` before returning.
- The screen is 128x64 pixels, 1-bit.
- Log with `FURI_LOG_E/W/I/D/T(tag, fmt, ...)` using a short, constant tag.

## Building

```powershell
ufbt
```

Or press `Ctrl+Shift+B` in VS Code (`Shift+Cmd+B` on macOS).

The result is `dist/hello_flipper.fap`. A successful build ends with an `APPCHK` line
reporting the target and API level, e.g. `Target: 7, API: 87.1`.

To clean build artifacts:

```powershell
ufbt -c
```

## Deploying to the device

1. Connect the Flipper over USB and close qFlipper (it holds the serial port open).
2. Run:

```powershell
ufbt launch
```

This builds, uploads the FAP to `/ext/apps/<fap_category>/`, and starts it immediately.

You can also run it from the device at any time: **Apps → Examples → Hello Flipper**.

### Manual deployment

If you prefer not to use `ufbt launch`, build with `ufbt`, then in qFlipper go to
**File Manager → SD Card → apps → Examples** and drag `dist/hello_flipper.fap` in.

### Viewing logs

```powershell
ufbt cli
```

Then at the `>:` prompt run `log` (or `log info` if you changed the default log level).
Press `Ctrl+]` to exit the serial console.

## Firmware and SDK versions

The SDK that uFBT builds against must match the firmware running on your Flipper. If
`ufbt launch` reports an SDK version mismatch:

```powershell
ufbt update      # pull the latest SDK
ufbt flash_usb   # flash firmware matching that SDK
```

This project was built against SDK release `1.4.3` (target 7, API 87.1). Custom firmware
distributions generally work too as long as their API level matches — no changes to the
source or manifest are required.

## Troubleshooting

| Symptom | Cause and fix |
| --- | --- |
| `ufbt: The term 'ufbt' is not recognized` | The virtualenv is not activated. Run `.\venv\Scripts\Activate.ps1`. |
| `ld.exe: .../venv/pyvenv.cfg: file format not recognized` | uFBT's default source glob is `*.c*`, which also matches `pyvenv.cfg` inside `venv/`. Fixed here by pinning `sources=["hello_flipper.c"]` in the manifest. Alternatively, keep the venv outside the app folder. |
| `Storage error: path '/ext/apps/Examples': unknown error` | The category folder does not exist on the SD card. Run `ufbt cli`, then `storage mkdir /ext/apps/Examples`. |
| `ufbt create` fails with `.github: Cannot create a file when that file already exists` | The scaffolder cannot merge into an existing `.github/`. Copy `.github/workflows/build.yml` from the template manually. |
| `hello_flipper_icons.h: No such file or directory` | `images/` is missing or `fap_icon_assets` is not set in the manifest. Either fix that or drop the include. |
| Device not found | Close qFlipper or anything else holding the serial port, then retry. |
| SDK version mismatch on launch | See [Firmware and SDK versions](#firmware-and-sdk-versions). |
| App builds but is missing from the menu | Check `fap_category`; the FAP installs under `SD Card/apps/<fap_category>/`. |
